# Contributing to SnapOrder

Thank you for helping improve SnapOrder.

Before opening a pull request:

1. Check existing issues and pull requests to avoid duplicates.
2. Keep the change focused; new features should start as a discussion.
3. Do not add paid gates, telemetry, remote locks, commissions, or public credit links.
4. Follow WordPress coding, security, accessibility, and internationalization conventions.
5. Add or update tests where behavior changes.
6. Run `composer test`, `composer lint`, `npm run test:js:syntax`, and `npm run build`.

Pull requests should explain the human reason for the change, its impact, and how it was validated. Never include customer data, credentials, database exports, or private environment files.
